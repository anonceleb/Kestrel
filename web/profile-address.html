The full pipeline, in this page: registry → vault → grant → label → depot resolve → shred

Every step below executes the transformed repo modules — services/vault, packages/registry (Beckn subscriber-signing envelopes), packages/labels (COSE_Sign1), packages/crypto (ChaCha20-Poly1305 envelope encryption), adapters/india-post (DIGIPIN-prefix routing). Pilot shape: the grant rides as an optional payload inside an existing Beckn action/on_action pair; the plaintext-address path stays available as a fallback, so no participant must upgrade on day one.

Steps are sequential; each prints the actual artifact it produced. Reload to start over.

1. Registry — genesis facilitator admits the LSP (signed write)

Beckn wire format: keyId="{subscriberId}|{keyId}|ed25519", digest is BLAKE2b-512 of the canonical body, signing string is the exact (created)/(expires)/digest: shape. Unsigned or non-facilitator writes throw — see break-it #7, #8.

—

2. Vault — store the address encrypted, bind a pairwise id

The record the vault persists (ciphertext, per-record HKDF key, AAD-bound to tenant|record) and the projection Zone 2 / the merchant is allowed to see. INV-1: no counterparty-held record may contain an address-shaped field.

—

3. Consent + grant — mint against the pairwise id

—

4. COSE label — minted in Zone 1, verified with public keys only

What gets printed on the parcel. verifyLabelOffline() takes only pre-synced public key material — no vault, no network. The claims carry no address-shaped field.

—

5. Depot resolve — the single online event

Audit record is written before decryption, in the same call. The routing port sees the plaintext transiently and emits a sortation code from a truncated 6-of-10 DIGIPIN prefix; the full DIGIPIN and address never leave the call frame.

—

6. Replay, then erase

Replay dies on the nonce burn. Erasure requires a facilitator-signed WriteAuth and destroys the record's shred salt — every ciphertext derived from it, including copies in backups, becomes unreadable.
