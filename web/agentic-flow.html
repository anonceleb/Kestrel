ACP already tokenized the payment. The address travels in the clear, one field over.

The Agentic Commerce Protocol (OpenAI/Stripe, released 2025-09-29) draws a line for payment data: it travels as a scoped, single-merchant, single-amount, expiring token. Fulfilment data does not — fulfillment_address is a plaintext object in the same request, visible to the agent runtime, the merchant, and any middleware that logs the body. The right column is the same request carrying a FulfilmentGrant instead — minted live by this page with the repo's packages/capability module.

Payment: a Stripe Shared Payment Token — one seller profile, one currency, one maximum amount, one expiry. Fulfilment: the subject's home address, in the clear, in every hop of the checkout path.

minting…

Minted in this page by the real mint(): HMAC-SHA256 over {id, caveats, chain}, secret held vault-side. The agent, the merchant, and anything logging this request hold a token that resolves to nothing without the vault — and resolves at most once. Redemption and failure modes: profile-address, try-to-break-it.

The turn loop — an agent holding a capability, never an address

The comparison above is a schema argument. This is the thing itself: seven turns, driven by the repository's own Vault, registry, consent ledger and capability modules running in this page. Watch the holdings row — neither the agent nor the merchant ever acquires an address, and the grant the merchant receives is strictly weaker than the one the agent held.

Turn 7 is the one worth staying for. It shows the boundary of attenuation, which is a property this project had described loosely until the loop was built: narrowing a grant transfers no authority. A fully registered courier holding a validly narrowed grant still cannot redeem it, because redemption is bound to the actor the subject consented to.

Facts as cited, checked against primary sources

  • ACP checkout schema — fulfillment_address as a plaintext Address object beside tokenized payment_data — schema version 2025-09-29, main branch of the ACP repository.
  • ACP was co-developed by OpenAI and Stripe, released 29 September 2025 (Stripe newsroom). Claims that did not verify against primary sources (Meta co-authorship; a 2026-04-17 date) are not made here.
  • Stripe Shared Payment Tokens are scoped to one seller profile, one currency, one maximum amount, one expiry. The payment/fulfilment asymmetry is structural, not a reading of intent.
